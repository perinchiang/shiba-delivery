# 验收失败根因先行协议（Root-Cause First Protocol）

> **核心纪律**：测试或截图验收不通过时，**禁止立刻猜数值微调并重跑**。先花 1 分钟完成定性，再做最小定点修改；同一缺陷连续 **2 轮** 自动修复仍未过关，必须熔断停止并上报 Patrick。

## 第一步：5 类根因归因（单选主因，可附次因）

1. **几何 / 坐标 / 比例偏差**
   - 典型表现：浮空、半截埋地、接缝裂开、穿模、角色手脚偏离握把/脚踏、道具过大或过小。
   - 排查手段：核对 Blender `-Y` → glTF `+Z` 轴向、0.84 缩放、世界坐标与高度采样函数，或跑 `tools/test-morning-riding.mjs` 数值断言。
2. **材质 / 光照 / 阴影 / Z-fighting**
   - 典型表现：面片闪烁黑斑、背板透穿、色彩偏离 `CITY_PALETTE`、发灰过曝、阴影切边或缺失。
   - 排查手段：查共面重叠、`side: DoubleSide`、depthWrite/polygonOffset、法线方向、阴影相机视锥。
3. **相机机位 / 遮挡 / 视口裁剪**
   - 典型表现：主体被红绿灯/屋檐/树冠挡住、UI 卡片在 `844×390` 横屏出屏或重叠、景深构图偏离目标。
   - 排查手段：区分是**游戏运行时镜头逻辑有问题**，还是仅仅 **Debug 预设机位参数不合适**。
4. **状态机 / 动画时序 / 输入竞态**
   - 典型表现：切场景状态残留、门/箱动画打断卡死、步行与骑行切回错位、双指触控吞点击。
   - 排查手段：查 `delivery.js` / `sequence.js` / `controls.js` 状态流转与重置钩子。
5. **QA 脚本 / 等待时机误报（工具本身问题）**
   - 典型表现：截屏拍在了加载中/动画未稳定帧、端口/服务未就绪、选择器过期。
   - 处理原则：**只修 QA 脚本或 `--wait`/`--hold-ms` 参数，严禁为了迎合脆弱测试去魔改游戏逻辑！**

## 第二步：路由与熔断决策

- **第 1 轮失败**：写 3 行根因诊断（现象 → 归类 → 根因假设）→ 针对性修复（若原为 Sol 执行且根因落在第 1/2 类复杂 3D/渲染问题，直接升级接力给 `gpt-6.2-astra`）→ 仅重拍受影响机位 + 1 个全局回归机位。
- **第 2 轮仍失败（触发熔断）**：
  - 立即停止继续自动修改！
  - 向 Patrick 汇报：① 第 1/2 轮对比截图路径；② 已验证排除的假设；③ 当前最可能的根因与 2–3 个备选决策方向。
