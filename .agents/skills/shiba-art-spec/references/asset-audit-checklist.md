# 资产合规审计清单（Shiba Delivery）

> **反虚假绿灯铁律**：每项必须基于实际命令、脚本统计或实图目视核查。缺失输入或无法测量时填 `NOT ASSESSED — <原因>`，严禁猜测填“通过”。

## 1. 管线合规、查库复用与源文件
- [ ] 是否已先查阅 `art/CATALOG.md` 且未重复造轮子（直接复用 / 公模换色换贴图 / 确有缺失才新建）？新增或变更是否已同步登记回 `art/CATALOG.md`？
- [ ] 是否严格遵守「纯 Blender 精建 + AI 2D PBR 贴图」管线，**未新增**纯代码方块建筑（`BoxBuilder`）、纯顶点色假材质或程序化 Canvas 糊字招牌？
- [ ] 每个 `.glb` 是否有配套可编辑的 `.blend` 源文件（若为构造脚本驱动，可无头复现 `blender --background --factory-startup --python-exit-code 2 --python <script>.py` 并落盘 `.blend`）？
- [ ] 通用道具是否已独立归口 `art/shared/props/` 并分离主色/贴图材质槽以支持一键换色换图（未焊死在单栋建筑内）？

## 2. 结构细节、美学质量与 Gate 1 审图
- [ ] 建筑是否具备真实墙厚、真凹陷门窗洞、室内纵深与厚实柔和倒角（无 Boolean 平面斜向阴影拉黑）？
- [ ] 机械/结构红线：无“用平板遮挡机械结构”（如单车传动/花鼓须真实建模）；遮阳棚向外下方倾斜、无多余违和装饰；外挂楼梯紧贴墙体收口或双侧配齐扶手；可通行走廊摆件克制留白。
- [ ] 文字与招牌：AI 原图无错字乱码；同店名跨招牌/暖帘/竖牌完全统一；主店招清晰立体（远看不糊成一坨）。
- [ ] Gate 1 Cycles 审图是否已实际查看日景全景、近景特写、交互特写、俯视结构与**暖光夜景**（确认室内/店面暖光真实透出）？

## 3. 坐标、比例与锚点
- [ ] 米制尺度与阿柴/载具（`0.84` 缩放）视觉协调，无巨人/微缩穿帮。
- [ ] Blender `-Y` 朝前导出为 glTF `+Z` 朝前，底部原点贴地（无悬空或半截埋地）。
- [ ] 涉及角色/载具/可步行楼梯改动后，`npm test`（含 `tools/test-morning-riding.mjs` 等断言）全过。

## 4. 游戏运行版体积、贴图与引用完整性（Gate 2）
- [ ] 用 `du -h` / `ls -lh` 检查运行版 `.glb` 与贴图体积是否经过减面、合批与压缩（区别于 `.blend` 高精母版，不把十几 MB 未优化母版直接塞进浏览器加载）。
- [ ] 共享贴图为 2 的幂次，遵循预算（通用无缝材质 `512`–`1024`，大海报/主图集上限 `2048`，透明用 PNG，不透明可压缩 WebP/JPG）。
- [ ] **孤儿资产与缺失引用**：Gate 2 资产是否在 `src/` 中真实引用，且所有路径在磁盘存在？（Gate 1 审图期可标注 `N/A — Gate 1 尚未接入 src/`）。

## 5. 实机渲染质量与性能预算（Gate 2）
- [ ] 材质槽克制，重复道具与建筑模块支持合批或 Three.js `InstancedMesh` 实例化。
- [ ] 无共面 Z-fighting、无背面剔除破洞、无跨时段光照异常（晨/昏/夜全时段检视）。
- [ ] 在真实 Chrome Metal `1280×800` 截图中核对 `#scene-perf`：目标 60 FPS，全帧含阴影 **≤ 250 draw calls**、总面数 **≤ 100 万**。

## 6. 审计结论枚举（按首个命中项裁定）
- `NON-COMPLIANT`：回退纯代码假建模、存在明显结构穿帮/Z-fighting、破坏接触断言、缺失引用或越过性能预算。
- `WARNINGS`：Gate 1 存在局部细节待精修，或 Gate 2 体积/材质槽仍有优化空间。
- `NOT ASSESSED`：有必检维度因处于 Gate 1 未进游戏或缺少运行测量未能实测（必须写明具体项）。
- `COMPLIANT`：当前阶段（Gate 1 或 Gate 2）全部适用维度均已实测且无问题。
