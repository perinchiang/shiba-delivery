## 1. 视觉定位与裁决测试

**一句话定位**：明媚温暖、**「真实街区比例与生活物件密度 × 吉卜力/风格化 PBR 干净材质」**的东亚海滨坡道小城（榕湾）——参考《夏天啦！20世纪的暑假》、镰仓/《如龙 6》尾道坡道空间结构与《福神事务所》的卡通打工人反差；可爱的动物与电动车放进紧凑方正的《如龙》式城市箱庭，不做写实脏旧铁锈贴图，靠清晰体块、丰富日常街具、区域色调、招牌语言和阳光海景讲故事。

**区域视觉进度**：越往市中心，颜色越冷、越整齐、越高，也越孤独。

| 区域（箱庭） | 轮廓与排布 | 色调与招牌 |
|---|---|---|
| 1 号箱庭：滨海旧镇（榕湾坡道镇） | 北高南低的方正紧凑坡道网格（约 `180m × 180m`），**已锁定方向 A（海滨下町 · 平顶杂居楼 + 外挂铁楼梯小巷）**，概念锚点见 [`docs/references/direction-a-seaside-zakkyo.jpg`](references/direction-a-seaside-zakkyo.jpg)：**70% 2–3 层平顶水泥/瓷砖商住杂居楼（一楼暖木门面/暖帘/贩卖机/墙脚杂物 + 可步行外挂墨绿烤漆铁楼梯 + 二楼开放式铁栏走廊/编号房门/排水管/空调外机 + 平顶女儿墙护栏）+ 30% 传统木构老铺混搭**，楼间打通 `2.5m` 穿楼小巷；坡底横穿海滨电车平交道口（踏切）、滨海大道与闪光蓝海 | 暖奶油/灰泥墙、鼠尾草绿混凝土楼板女儿墙、墨绿烤漆铁件、暖木门面与红暖帘、干净瓷砖与柏油石砌挡土墙，**干净温暖不脏旧**；按菜系自然使用中/日/泰等多语种店招 + 简笔图标，门牌（含二楼 `201`/`202`）用数字/字母 |
| 2 号箱庭：现代镇区 / 商圈 | 中等高度（4–6 层），较整齐的公寓与商业广场 | 中性奶油与灰绿；多语种商铺招牌 |
| 终极箱庭：市中心 | 神室町/CBD 式高楼、玻璃幕墙、宽大十字路口 | 冷蓝、灰白，干净但冷漠；以英文商业招牌与写字楼标识为主 |

遇到视觉分歧时，按以下 3 条测试裁决：

1. **辨识度优先于写实细节**：当繁复写实纹理与中远距轮廓可读性冲突时，选大色块、清晰体块与干净边缘。门牌号、招牌等玩法相关文字必须在骑行距离可读。
2. **主体永远压住背景**：阿柴（暖橘/奶油毛色 + 黄色头盔 + 黄黑外卖冲锋衣 + 黄色餐箱）与车辆在任何区域、任何时段都必须一眼跳出，建筑墙面与路面保持低对比烘托。
3. **可玩与可达优先**：任何路缘、树池、店招、红绿灯或装饰 props 不得遮挡主视角操作路线或制造假碰撞；步行/骑行通道必须一眼可辨。

## 2. 色板、渲染风格与时段

- **色板事实源**：[`src/morning/city-palette.js`](../src/morning/city-palette.js) 中的 `CITY_PALETTE`。新增建筑、街具、props **必须优先复用或微调自色板**；各区域色调确定后，以按区域分组的方式扩展同一文件，不另建平行色板。
- **渲染风格【已确定：A 柔和绘本风 · 风格化 PBR（Stylized PBR）】**：吸收《如龙 6》尾道的真实建筑比例与生活物件密度，但**不走写实脏旧/8K 摄影贴图**；保留柔和 PBR，提高粗糙度、压低塑料高光，阴影用冷色填充而非中性灰，轻辉光，按时段调色，雾不把画面洗灰。实现见 `src/morning/render-style.js`。
  - **S1 对比结论**（同机位 4 风格 × 4 时段实测，2026-11-23）：
    - **B 卡通渲染 + 描边：不采用。** 阶梯光照和描边会把建筑的方块造型凸显出来，反而显得假。
    - **C 像素化 3D：不采用。** 本质是低分辨率放大的"假像素"，中文招牌糊成色块，阿柴表情细节丢失。
    - **A 柔和绘本风（风格化 PBR）：采用**，看建筑最耐看，也与圆润可爱的阿柴最协调。4 个时段已完成调校并设为默认（`b2ad874`），B、C 代码路径已移除。
  - **去灰盒与程序化微质感（2026-11-24 已实机验证）**：在柔和 PBR 之上通过 `onBeforeCompile` 统一叠加程序化厚涂与结构微质感——建筑自动识别坡顶瓦楞肋纹、水粉抹灰墙面、深檐/腰线冷蓝阴影、砖石挡土墙接缝、柏油颗粒标线与天光玻璃反射，并保留夜晚窗格顶点色识别；地面、草坡、树冠与路面共享同一套世界空间慢移云影。
- **时段【已确定做 4 个】**：早晨、中午、傍晚、夜晚。每个时段是一组数据驱动的参数（太阳方向/颜色/强度、天空与环境光、雾、阴影色调、调色、自发光与辉光强度），按游戏时钟平滑过渡。
  - 夜晚依靠**自发光材质 + 地面假光斑 + 辉光**，不使用大量实时点光源。
  - 任何风格必须在 4 个时段下都通过裁决测试，只在早晨好看不算合格。
- 远景用雾压低对比度；3D 天空云环必须输出天空深度（`clip.xyww`）防止裁切远山坡与树冠；**禁止在运行时动态翻转 `DirectionalLight.castShadow`**（会触发全场景 Shader 重编译导致跨区卡顿），阴影策略保持全程稳定（脚底接触阴影 + 顶点色 AO，或固定阴影配置）。

## 3. 比例、造型与坐标红线

- **单位与缩放**：全项目使用**米制**。阿柴与车辆（当前为小摩托外形，后续择机按方向 A 概念图 [`docs/references/direction-a-seaside-zakkyo.jpg`](references/direction-a-seaside-zakkyo.jpg) 与 `neon-delivery` 踏板车设计替换为圆润明黄电动车，再扩展多款升级车型）在游戏中统一按 **`0.84`** 放入街景；阿柴采用《猛兽派对》式单张连续四边面细分网格（一体无缝圆肩 + 自然垂落饱满双骨长软臂 + 贴面黄黑短款冲锋衣），彻底避免腋窝粘连、L 型凹槽与外挂断缝，同时保持地面与车体接触锚点正确。
- **坐标系约定**（详见 [`art/morning/README.md`](../art/morning/README.md)）：
  - Blender 源场景：X 为横向、Z 向上、车头朝 `-Y`。
  - 导出 glTF / Three.js：Y 向上、车头朝 `+Z`。
  - 角色/摩托接触锚点（`Seat_Contact`、`Grip_L/R`、`Footrest_L/R`、`Cargo_Floor`、`Cargo_Approach`、`soleDepth`）由脚本与游戏共享，修改造型必须同步保活 `npm test` 几何断言。
- **树木与自然造型【2026-11-24 已定新基线】**：
  - **树木（[`src/morning/stylized-trees.js`](../src/morning/stylized-trees.js)）**：修长弯曲主干 + 伸入叶团的分叉树枝 + 512×512 程序化手绘叶簇透明片（含透明像素溢色防黑边）+ 球形法线转移微曲叶卡（片段内修正 `DoubleSide` 背面朝向，呈现柔和透气的油画云团感）+ 树底软接触阴影；支持 `tall` / `wide` / `compact` / `citrus`（庭院柑橘树）变体，老街与稻田旧树（[`art/countryside/kit.py`](../art/countryside/kit.py)）后续按需迁移。
  - **草地、野花与坡地（[`src/morning/stylized-meadow.js`](../src/morning/stylized-meadow.js)、[`src/morning/coastal-sample.js`](../src/morning/coastal-sample.js)）**：GPU 实例化 3 叶非对称弯曲草簇（背面朝上法线修匀、草根与地形共用世界空间色调实现无缝衔接）+ 聚落野花；住宅与道路保持平整台地与走廊，外围平滑抬升出 `10–15°` 缓坡。
- **街景尺度参考**：老街店前人行道宽约 4.7 m，树池临车道一侧用凸起陶砖围边，店门侧保持连续步行空间；路口与横街街具按角色身高与车宽对照摆位，不出现“巨人路灯”或“玩具门框”。

## 4. 资产生产管线边界

### 4.1 资产分工与先查库铁律

- **工具职责分工**：**美术资产（`.blend` / `.glb` + 真实风格化 2D PBR 贴图/图集）**负责公模道具、角色素体、英雄地标与表面质感；**代码（Three.js / 脚本）**负责灰盒玩法验证、地形与路网生成、批量实例化拼装、光影/水面/云影特效与动态文本。不再强求纯代码脚本盲写高精度建筑与手绘式 Canvas 纹理。
- **开工先查台账（三选一）**：制作任何 3D 模型、场景道具或贴图前，必须先查阅 [`art/CATALOG.md`](../art/CATALOG.md) 并写明决策：**① 直接复用**（改位置/缩放/调色）→ **② 公模换贴图或换局部配件**（如易拉罐换包装贴纸、贩卖机换面板图集、角色布娃娃素体换头与衣服贴图）→ **③ 确认台账确无同类时才新建**，且通用道具必须独立导出归口共享库并同步登记回 [`art/CATALOG.md`](../art/CATALOG.md)。

### 4.2 各类资产生产方式

| 类别 | 默认生产方式 | 源与产物约定 |
|---|---|---|
| 通用公模与街头道具（贩卖机、空调、盆栽、饮料筐、单车、电杆、易拉罐/餐盒等） | 可视化 `.blend` 建模/精修或脚本导出 `.glb`，**规范展 UV** 以便靠换贴图/换色批量复用 | 渐进收敛至 `art/shared/props/` 维护全游戏唯一公模；禁止将通用小道具焊死在单栋建筑内 |
| 角色与 NPC 素体公模 | **「布娃娃」通用素体 + 共享骨架**，靠换头部部件与服饰贴图扩展不同小动物/居民 | 主角与现行摩托位于 `art/morning/`（造型冻结）；后续通用 NPC 素体归口 `art/shared/characters/` |
| 区域建筑模块与重点地标 | 支持 **Blender 可视化 `.blend` 建模/精修导出 `.glb`** 或 **Blender Python 模块脚本** + Three.js 程序化拼装 | 源与产物并置在 `art/<zone>/`（如 `art/town/`）；模块间可共用共享贴图与公模道具 |
| 贴图、店招印花与 PBR 材质 | **优先真实风格化 2D 图片贴图与共享图集 / Trim Sheet**（Color + Roughness + Normal + Emissive；支持 AI 生图精修、手绘或风格化材质库），用有限共享材质槽拉开《动森》/《女神异闻录》式质感反差（哑光灰泥 / 半光烤漆金属 / 釉面瓷砖 / 玻璃）；程序化 Canvas 退居动态多语言文本、灰盒占位与轻特效 | 共享贴图归口 `art/shared/textures/`；遵循 2 的幂次尺寸，按需使用 `512`–`2048` 压缩贴图，不为单件小道具独占超大贴图 |
| 道路、区域间连接路、远景、批量布局与特效 | Three.js 程序化生成 + 按材质合批 / `InstancedMesh` | 代码在 `src/morning/`，参数集中可调 |
| 店铺与住宅室内 | 复用小房间基础模板 + 公模柜台/道具换配区分 | 不追求室内外物理 1:1 对应 |

**Blender 资产硬规则：**
- 所有硬边加倒角（Bevel），这是统一「厚实圆润」手感的关键；程序化方块也应改用圆角几何。
- 支持规范 UV + 共享风格化 PBR 贴图与离线烘焙 AO / Lightmap（同时兼容既有顶点色 AO 与 [`src/morning/coastal-sample.js`](../src/morning/coastal-sample.js) 程序化建筑微质感），**不做写实脏污/生锈贴图**；不再强求“只靠顶点色、不画建筑贴图”。
- 窗户、招牌、灯箱等**必须预先标记自发光区域**（独立 Emissive 贴图区域、独立材质或顶点色通道，如窗玻璃 `0x527a78`），供夜晚时段使用。
- **3D 样角先行**：制作新区域前，跳过 2D 风格重绘（paintover），直接用 Blender 制作约 **10m × 10m 的 3D 样角切片**放进实机验证材质、比例、Draw Calls 与骑行手感，确认后再批量扩展。

## 5. 性能与渲染硬预算

基线环境：Mac M2 / 中端笔记本 Chrome Metal，`1280×800`，`DPR 1`，目标稳定 **60 FPS**（数据来源：[`FIRST-ROAD.md`](FIRST-ROAD.md)）。

| 指标 | 预算 / 约束 | 核验方式 |
|---|---|---|
| 全帧 Draw Calls（含阴影） | 全部主城箱庭与机位严格控制 **≤ 250 calls** | Debug 面板 `#scene-perf` / `capture-scenes.mjs` |
| 全帧三角形数 | 目标 **≤ 100 万** | 性能核验与 Blender 导出面数控制 |
| 合批与实例化 | 同区块静态楼体/路面按材质合批；树木、路灯、电杆、稻穗、护柱等重复物**必须 `InstancedMesh`** | 代码审查 |
| 渲染防坑 | 禁止共面贴片导致 Z-fighting（如背板/招牌/标线需留明确法向偏移或单面剔除）；动态对象按需 `dispose` | 代码审查 + 多角度近景截图 |

## 6. UI / HUD 视觉约束

- 对白框、卡片与标签沿用 [`animal-island-ui`](../package.json) 体系与 `Noto Sans SC` 字体，圆润温暖、底部居中不遮主角。
- 所有新增或修改的 HUD / 手机 / 地图 / 对白界面，必须同时在 **PC 桌面（`1280×800`）** 和 **移动横屏（`844×390`）** 两个视口下截屏验证，确保无文字截断、按钮重叠、出屏或遮挡核心操作区。
- Debug 控件仅在开发模式、GitHub Pages 预览（`VITE_SCENE_DEBUG=1`）或 `?debug=1` 下可见；普通构建默认隐藏。
