## 1. 视觉定位与美学基准【已最终定调】

**一句话定位**：明媚温暖、**「微缩手办感（《动森》式圆润厚实倒角与立体精致度）× 东亚海滨真实生活密度 × 吉卜力/风格化 PBR 干净手绘质感」**的海滨坡道小城（榕湾）。不做写实脏旧铁锈，也**彻底摒弃纯代码方块堆砌感**；靠真实结构建模、AI 手绘 PBR 表面材质、饱满日常街具，以及**入夜后“真的有人在住”的暖光室内透光**讲故事。

**两大视觉锚点（唯一对齐基准）：**
1. **概念与构图锚点**：[`docs/references/direction-a-seaside-zakkyo.jpg`](references/direction-a-seaside-zakkyo.jpg)（方向 A · 海滨下町平顶杂居楼 + 外挂铁楼梯小巷 + 电车道口与蓝海）。
2. **实机 3D 工艺锚点**：[`art/town/haikaze-hero/Haikaze-Hero.blend`](../art/town/haikaze-hero/Haikaze-Hero.blend)（海风庄 v3 · 90 分定调基准）与 [`art/shared/props/Shared-Props.blend`](../art/shared/props/Shared-Props.blend)（首批 10 件共享公模）。

**区域视觉进度**：越往市中心，颜色越冷、越整齐、越高，也越孤独。

| 区域（箱庭） | 轮廓与排布 | 色调与招牌 |
|---|---|---|
| **1 号箱庭：滨海旧镇（榕湾坡道镇）** | 北高南低的紧凑方正坡道网格（约 `180m × 180m`）：70% 2 层平顶水泥/瓷砖商住杂居楼（一楼暖木门面/暖帘/贩卖机/墙脚杂物 + 外挂墨绿烤漆铁楼梯 + 二楼开放式走廊/门牌/圆铜外卖挂钩/空调外机 + 平顶天台女儿墙与水箱晾衣绳）+ 30% 传统木构老铺混搭，楼间打通 `2.5m` 穿楼小巷；坡底横穿海滨电车道口与闪光蓝海 | 暖奶油手涂灰泥、鼠尾草绿混凝土、墨绿烤漆铁件、暖调雪松木、绯红麻布暖帘、糖果釉面马赛克瓷砖，**干净温暖不脏旧**；按菜系自然使用中/日/泰等多语种清晰店招，门牌（如 `201`/`202`）用数字/字母 |
| **2 号箱庭：现代镇区 / 商圈** | 中等高度（4–6 层），较整齐的公寓与商业广场 | 中性奶油与灰绿；多语种商铺招牌 |
| **终极箱庭：市中心** | 神室町 / CBD 式高楼、玻璃幕墙、宽大十字路口 | 冷蓝、灰白，干净但冷漠；以英文商业招牌与写字楼标识为主 |

**视觉分歧 3 条裁决测试：**
1. **辨识度优先于琐碎写实**：当繁复写实噪点与中远距轮廓可读性冲突时，选厚实倒角、清晰体块与干净色彩分组。店招、门牌、挂钩等玩法相关物件在骑行与步行距离必须一眼可读。
2. **主体永远压住背景**：阿柴（暖橘/奶油毛色 + 黄头盔 + 黄黑外卖服 + 黄餐箱）与电动车在任何区域、任何时段都必须一眼跳出，墙面与路面保持柔和低对比烘托。
3. **可玩与可达优先**：任何路缘、花盆、单车、招牌或街具不得阻塞步行/骑行通道或制造假碰撞；走道与楼梯动线保持克制留白。

## 2. 核心生产管线：纯 Blender 建模 + AI 2D PBR 贴图【强制执行】

### 2.1 彻底废除“纯代码假建模与程序化贴图”

自本版规范生效起，**全面废除早期过渡期的纯代码美术路线**，所有新做与重做资产严格执行以下边界：

- **禁止再做（早期旧代码资产已彻底下线并归档于 `archive/early-prototype`）**：
  - ❌ 禁止用 Three.js 代码手拼建筑或街头道具；
  - ❌ 禁止用 `BoxBuilder` 式百块方块硬拼建筑脚本（如已归档的旧版 `art/town/coastal-town-kit.py`）；
  - ❌ 禁止用纯顶点色假装材质，或用 `onBeforeCompile` 程序化着色器给素模“假装贴砖纹/瓦楞”（旧补丁随新资产替换一并退役）；
  - ❌ 禁止用前端 Canvas / Pillow 简笔画直接糊核心招牌、菜单、海报或墙面肌理（如已归档的 `src/morning/coastal-detail-atlas.js`）。
- **纯 Blender + AI 贴图负责什么**：全部玩家可见 3D 美术资产——建筑主体与模块化构件、门窗/楼梯/屋顶细节、全游戏共享公模道具、载具、主角与 NPC 材质贴图。
- **Godot 4.7 Forward+ 代码与场景负责什么**：原生 `.blend` 导入与合批实例化（`MultiMeshInstance3D`）、坡道地形与碰撞体、实时 `AgX + VoxelGI / SDFGI + SSIL + SSAO + SSR` 光影与 4 时段切换、广角软阴影实用灯与夜间自发光驱动、水面/微风/拉面热气等轻特效、骑行物理与桌面 HUD/手机界面。

### 2.2 Blender 建模标准（微缩手办级真实结构）

所有新建筑与道具必须用真正的 Blender 建模能力制作，并保存可直接双击打开精修的 `.blend` 源文件（可由干净的 Blender Python 构造脚本驱动复现，但必须产出真实拓扑与可编辑 `.blend`）：

- **真实墙厚与真开口**：建筑外墙保持真实厚度（约 `0.26–0.30m`），使用 **Boolean 真挖深窗洞、门洞与内凹店门玄关**，严禁在平面墙上贴假窗纸片。
- **真实室内纵深**：每个可见门窗背后构建简易 3D 室内盒（暖色内墙、立体折皱窗帘、一楼店铺吧台/碗具/吊灯等），支撑白天景深与夜晚暖光透出。
- **厚实圆润倒角（Bevel）**：所有硬边统一做多段柔和倒角，配合平滑着色与平面法线控制（避免 Boolean 平面出现斜向拉黑条纹），呈现微缩手办般的温润手感。
- **真曲线与真结构**：管线、电线、单车车架/辐条/传动、空调风扇与同心圆铁丝网、暖帘飘动布面、车削花盆/汽水瓶/水箱等，一律用 Curve / Lathe / Subdivision / Solidify 做真 3D 结构，**禁止用一整块板子盖住机械结构敷衍交差**。
- **规范 UV 展开**：建筑大面采用无拉伸连续贴图投射（Box/Triplanar 或规范 UV），招牌、海报、菜单、公模局部均拆出独立干净 UV 槽，方便一键换图与烘焙。

### 2.3 AI 手绘 2D PBR 贴图与清晰字体管线

共享贴图统一归口 [`art/shared/textures/`](../art/shared/textures/)，遵循实测跑通的三步管线：

1. **AI 手绘无字原图（`ai_*.png`）**：使用实测笔触最稳的图像模型（当前基线 **`gpt-image-2.6-sunburst`**）生成**纯无字手绘插画与无缝材质底图**（奶油手涂灰泥、鼠尾草绿混凝土、雪松木板、倒角地砖、窑变釉面马赛克瓷砖、粗麻织物、黑板粉彩画、冷面海报、贩卖机饮料海报等），严禁直接把 AI 乱码汉字带进资产。
2. **文字与招牌制作铁律（杜绝粗糙糊字）**：
   - **海报 / 菜单 / 暖帘布印**：在无字 AI 原图上通过 [`compose_ai_textures.py`](../art/shared/textures/compose_ai_textures.py) 叠印高质量排版文字，并按底图粉尘/织物明度做轻融合，确保近看像真实印刷/粉笔字、远看不发糊；
   - **主店招与门面大字**：禁止用低辨识度细长纯平贴图糊弄！主招牌优先采用 **AI 手绘暖木/老漆底板 + Blender 3D 立体挤出字 / 浮雕字牌**（或高对比厚实书法字体 + 立体边框 + 招牌射灯），确保远中近距轮廓锐利；
   - **店名一致性**：同一店铺的横招、暖帘、竖牌、黑板菜单必须统一店名与语种，不得出现“横招写海风、暖帘写潮风”之类打架现象。
3. **自动衍生 PBR 通道与热覆盖**：由原图衍生切线空间 `Normal`（`_normal.png`）与按材质区分的 `Roughness`（如釉面砖高光 `0.16` vs 砖缝哑光 `0.58`）；任何贴图均支持在同目录放 `custom_<文件名>` 一键覆盖为人工手绘精修图。

### 2.4 共享公模库与一键变体体系（开工必查台账）

制作任何 3D 道具、角色或贴图前，**必须先读 [`art/CATALOG.md`](../art/CATALOG.md)** 并写明三选一决策：**① 直接复用** → **② 公模换色/换贴图/换配件** → **③ 确认缺失后新建并回写台账**。

| 资产类别 | 归口路径 | 复用与变体机制 |
|---|---|---|
| 通用街头与室内公模 | [`art/shared/props/`](../art/shared/props/)（总源 `Shared-Props.blend` + 独立 `.glb`） | **严禁把通用道具焊死在单栋建筑内**。每个公模拆分「主漆面/瓶身材质槽」与「海报/贴纸 UV 槽」，方便在 Blender 或 Three.js 中**一键换色**（如单车车架、汽水瓶与饮料筐、花盆）或**一键换图**（如贩卖机海报、A 字黑板菜单、店招） |
| 共享风格化 PBR 贴图库 | [`art/shared/textures/`](../art/shared/textures/) | 全镇建筑与公模共用同一套无缝材质组（灰泥/混凝土/木板/地砖/瓷砖/布料）与独立海报槽，避免重复生图与显存浪费 |
| 区域建筑套件与地标 | `art/<zone>/`（如 `art/town/haikaze-hero/`、后续 `art/town/modules/`） | 建筑壳体共享 `art/shared/textures/`，全部小道具从 `Shared-Props.blend` 实例化引用；先出标杆楼，再拆成标准化外立面/门面/楼梯/屋顶模块拼装整片街区 |
| 角色、载具与 NPC 素体 | 主角/现行车在 `art/morning/`；后续通用 NPC 素体建于 `art/shared/characters/` | NPC 采用共享「布娃娃」素体与骨架，换头、耳尾与服饰贴图；**新电动车与后续角色/载具统一采用本管线（Blender 精建 + AI/PBR 贴图）**，保留既有骑姿锚点契约 |

## 3. 色彩、光影与“有人居住”的 4 时段氛围

- **色板事实源**：本节下表与 [`art/town/haikaze-hero/build_haikaze_hero.py`](../art/town/haikaze-hero/build_haikaze_hero.py) 中的校准色板。新增建筑、街具与 AI 贴图色彩校准（AgX / ACES 下避免强光发白或暗部死灰）均与该色板协调，按区域扩展，不另建平行色板。
- **材质反差法则**：用有限共享材质槽拉开触感反差——**哑光手涂灰泥**（Roughness `0.75–0.82`）vs **半光烤漆墨绿铁件**（Roughness `0.30` + Clearcoat）vs **高光糖果釉面瓷砖**（Roughness `0.16`）vs **拉丝黄铜五金**（挂钩/门把）vs **温润雪松木** vs **次表面暖光灯笼/窗帘**。
- **4 个时段（早晨 / 中午 / 傍晚 / 夜晚）**：数据驱动平滑过渡（太阳方向与色温、天空渐变、冷蓝阴影填充、远景轻雾、自发光与辉光），**所有核心建筑必须在日景与暖光夜景下同时通过审图**。
- **“有人居住”的暖光夜景标准【核心卖点】**：
  - 夜晚靠**真实内凹房间背墙暖光 + 背光透亮立体窗帘 + 一楼店铺暖光外溢 + 门廊灯/提灯/贩卖机展示窗自发光 + 烘焙 AO/Lightmap + 少量关键暖光池/假光斑 + 轻辉光（Bloom）**共同营造；
  - 不使用海量实时投影点光源拖垮帧率，也不允许夜晚建筑变回死黑方块或单薄贴纸亮块；
  - 禁止运行时动态翻转 `DirectionalLight.castShadow`（避免全场景 Shader 重编译卡顿），阴影策略保持稳定；3D 天空云环输出天空深度（`clip.xyww`）。

## 4. 两关制生产与验收流程（Gate 1 → Gate 2）

新地标建筑、建筑模块套组、关键载具或大类公模一律走**两关制**，彻底告别“盲改完塞进游戏碰运气”：

1. **Gate 1 · Blender 高精母版审图（先定美术上限）**
   - 在独立目录产出可编辑 `.blend`、高精 `.glb` 与全套共享公模/贴图；
   - 使用 Cycles（Metal GPU）渲染标准 **5 张验收图**（`output/blender-qa/<asset>/`）：① 日景 3/4 全景、② 门面近景特写、③ 关键交互区特写（如 201/202 门钩与走廊）、④ 俯视楼梯与天台结构、⑤ **暖光夜景 3/4 全景**（另附公模展示图与 AI 贴图总览）；
   - 先在 Blender 里打磨细节，**直到目视审图过关（90+ 分）再进入 Gate 2**。
2. **Gate 2 · Godot 4.7 原生 `.blend` 直导与 Forward+ 实机验收（95%+ Cycles 还原 + 流畅帧率）**
   - 通过 [`tools/sync_blender_to_godot.py`](../tools/sync_blender_to_godot.py) 从过关的 `.blend` 母版生成 Godot 规范 `.blend`（将 Cycles 专属 `AmbientOcclusion`/`BOX` 节点转为标准 UV `Principled BSDF` 并把静态不透明件合并为多材质网格，保留 100% 原始倒角几何与 PBR 材质，无需激进减面或 2K 烘培光图降质）；
   - 由 Godot 4.7 内置 Blender 导入器直导进 `game/assets/`，重烘 `VoxelGI` 并校准 `AgX + SSIL + SSAO + SSR + 广角软阴影 SpotLight3D` 与 13 组动态自发光材质；
   - 运行 `./game/run.sh -- --capture-qa output/qa/<slug>` 核验 4 时段实机截图、0 报错与稳态帧率，并发布 GitHub Pages HTML 图文对比报告供 Patrick 远程审图。

## 5. 比例、结构细节与坐标红线

- **单位与坐标系**：全项目采用**米制**。Blender 源空间 X 横、Z 上、朝前 `-Y`；导出 glTF / Three.js 为 Y 上、朝前 `+Z`。原点贴地（`Z=0`），便于 `InstancedMesh` 摆放。
- **主角与载具基准**：游戏中统一按 **`0.84`** 放入街景；保持既有接触锚点契约（`Seat_Contact`、`Grip_L/R`、`Footrest_L/R`、`Cargo_Floor`、`Cargo_Approach`、`soleDepth`），修改角色或载具必须保活 `npm test` 几何断言（详见 [`art/morning/README.md`](../art/morning/README.md)）。
  - *现状备注*：现行主角阿柴与小摩托（`art/morning/`）仍是早期 Blender Python 纯色/极简贴图资产，造型与骨架冻结保活；后续新电动车直接用本版 Blender + AI PBR 管线全新制作，主角择机补充同水准 PBR 材质贴图。
- **实测沉淀的结构细节红线（交付前逐条必查）**：
  1. **机械道具真结构**：单车等近景车辆必须做出真实牙盘/曲柄/脚踏/链条传动与轮毂/花鼓结构，不得用平板方块遮盖。
  2. **建筑构件物理合理**：遮阳棚必须从墙面向外**下方**自然倾斜，不做违和的多余圆弧装饰；外挂铁楼梯必须**紧贴墙体收口**（仅外侧单扶手）**或**在留缝时**双侧配齐扶手**，杜绝悬空缝隙与单边无护栏隐患。
  3. **招牌清晰与店名统一**：同一店铺所有招牌/暖帘/竖牌文字一致，主店招拒绝糊成一团的细长平面贴图。
  4. **通道克制与留白**：二楼走廊、门口、人行道摆件克制（例如二楼植物精简至 1–2 盆点缀），保持清爽动线与视觉呼吸感。
- **自然植被基线**：后续在 Godot 4.7 中以 Blender 柔和圆润团簇树冠与 `MultiMeshInstance3D` 实例化草坡野花重建，保持与海风庄一致的暖明媚色调（不复刻纯代码简陋草片）。

## 6. 性能与渲染硬预算（Godot 4.7 Desktop Forward+）

基线环境：Mac M2 Air（Metal 4.0） / 中端 PC（Vulkan），`1280×800` 及 `1920×1080`，目标流畅 **45–60 FPS**。

| 指标 | 预算 / 约束 | 核验方式 |
|---|---|---|
| 静态建筑合批 | 建筑通过 `sync_blender_to_godot.py` 合并为 3 个多材质完整网格（不透明/玻璃/背景），避免上千个零散节点爆掉阴影 Pass | Godot 实机 Debug 面板 / `metrics.json` |
| 实用光源阴影 | 夜景实用灯优先使用广角 `SpotLight3D`（1 张阴影图替代 6 面立方体阴影），每块街区控制核心投影灯数量 | `./game/run.sh -- --capture-qa` |
| 实例化复用 | 通用街具公模（贩卖机、空调、饮料筐、单车、花盆、路灯）与植被使用 Godot `MultiMeshInstance3D` 或共享场景实例 | 代码与场景审计 |
