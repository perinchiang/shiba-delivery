## 1. 视觉定位与裁决测试

**一句话定位**：圆润厚实的风格化东亚滨海小城（榕湾）——可爱的动物与车，放进一座干净温暖、有贫富落差的城市里；借鉴日系/沿海小镇的错落排布，不做生锈肮脏的写实城中村，靠统一的造型语言、区域色调、招牌语言和时段光影讲故事。

**区域视觉进度**：越往市中心，颜色越冷、越整齐、越高，也越孤独。

| 区域 | 轮廓与排布 | 色调与招牌 |
|---|---|---|
| 滨海旧镇（起点：老街 + 独栋住宅区） | 低矮错落、紧凑窄巷；住宅区以 4 栋一组的围墙小独栋（含小院、门口姓氏/门牌）围出街口，搭配圆润空调外机与电线 | 暖色奶油、淡瓷砖与橘暖点缀，**干净温暖不脏旧**；按菜系自然使用中/日/泰等多语种店招 + 简笔图标 |
| 现代镇区 / 商圈 | 中等高度，较整齐 | 中性奶油与绿色；多语种商铺招牌 |
| 市中心 | 高楼、玻璃、宽路 | 冷蓝、灰白，干净但冷漠；以英文商业招牌与写字楼标识为主 |

遇到视觉分歧时，按以下 3 条测试裁决：

1. **辨识度优先于写实细节**：当繁复写实纹理与中远距轮廓可读性冲突时，选大色块、清晰体块与干净边缘。门牌号、招牌等玩法相关文字必须在骑行距离可读。
2. **主体永远压住背景**：阿柴（暖橘/奶油毛色 + 黄色头盔 + 黄黑外卖冲锋衣 + 黄色餐箱）与车辆在任何区域、任何时段都必须一眼跳出，建筑墙面与路面保持低对比烘托。
3. **可玩与可达优先**：任何路缘、树池、店招、红绿灯或装饰 props 不得遮挡主视角操作路线或制造假碰撞；步行/骑行通道必须一眼可辨。

## 2. 色板、渲染风格与时段

- **色板事实源**：[`src/morning/city-palette.js`](../src/morning/city-palette.js) 中的 `CITY_PALETTE`。新增建筑、街具、props **必须优先复用或微调自色板**；各区域色调确定后，以按区域分组的方式扩展同一文件，不另建平行色板。
- **渲染风格【已确定：A 柔和绘本风】**：保留 PBR，提高粗糙度、压低镜面高光，阴影用冷色填充而非中性灰，轻辉光，按时段调色，雾不把画面洗灰。实现见 `src/morning/render-style.js`。
  - **S1 对比结论**（同机位 4 风格 × 4 时段实测，2026-11-23）：
    - **B 卡通渲染 + 描边：不采用。** 阶梯光照和描边会把建筑的方块造型凸显出来，反而显得假。
    - **C 像素化 3D：不采用。** 本质是低分辨率放大的"假像素"，中文招牌糊成色块，阿柴表情细节丢失。
    - **A 柔和绘本风：采用**，看建筑最耐看。4 个时段已完成调校并设为默认（`b2ad874`），B、C 代码路径已移除。
- **时段【已确定做 4 个】**：早晨、中午、傍晚、夜晚。每个时段是一组数据驱动的参数（太阳方向/颜色/强度、天空与环境光、雾、阴影色调、调色、自发光与辉光强度），按游戏时钟平滑过渡。
  - 夜晚依靠**自发光材质 + 地面假光斑 + 辉光**，不使用大量实时点光源。
  - 任何风格必须在 4 个时段下都通过裁决测试，只在早晨好看不算合格。
- 远景用雾压低对比度；**禁止在运行时动态翻转 `DirectionalLight.castShadow`**（会触发全场景 Shader 重编译导致跨区卡顿），阴影策略保持全程稳定（脚底接触阴影 + 顶点色 AO，或固定阴影配置）。

## 3. 比例、造型与坐标红线

- **单位与缩放**：全项目使用**米制**。阿柴与车辆（当前为小摩托外形，待替换为电动车；后续有多款电动车）在游戏中统一按 **`0.84`** 放入街景；阿柴采用《猛兽派对》式单张连续四边面细分网格（一体无缝圆肩 + 自然垂落饱满双骨长软臂 + 贴面黄黑短款冲锋衣），彻底避免腋窝粘连、L 型凹槽与外挂断缝，同时保持地面与车体接触锚点正确。
- **坐标系约定**（详见 [`art/morning/README.md`](../art/morning/README.md)）：
  - Blender 源场景：X 为横向、Z 向上、车头朝 `-Y`。
  - 导出 glTF / Three.js：Y 向上、车头朝 `+Z`。
  - 角色/摩托接触锚点（`Seat_Contact`、`Grip_L/R`、`Footrest_L/R`、`Cargo_Floor`、`Cargo_Approach`、`soleDepth`）由脚本与游戏共享，修改造型必须同步保活 `npm test` 几何断言。
- **树木与自然造型**：短胖蜜棕树干 + 圆根贴地 + 连成一体的偏心分层冠面 + 立体宽叶顶点色明暗（详见 [`art/countryside/kit.py`](../art/countryside/kit.py) 与 [`FIRST-ROAD.md`](FIRST-ROAD.md)）。
- **街景尺度参考**：老街店前人行道宽约 4.7 m，树池临车道一侧用凸起陶砖围边，店门侧保持连续步行空间；路口与横街街具按角色身高与车宽对照摆位，不出现“巨人路灯”或“玩具门框”。

## 4. 资产生产管线边界

| 类别 | 默认生产方式 | 源与产物约定 |
|---|---|---|
| 区域建筑与街区模块（围墙小独栋、老街门面、窗、阳台、空调外机、晾衣竿、电线、门牌、院门等） | **Blender 模块套件**（每区域约 15–25 个模块，住宅区以 4 栋一组的围墙小独栋为基本拼装单元）+ Three.js 程序化拼装 | 源脚本与产物并置在 `art/<module>/`；不为每栋楼单独建模 |
| 店招与门牌 | 程序化 Canvas 自动图集生成（保留防夜曝亮度上限），按菜系/区域自然使用多国语言（中/日/泰/英）+ 简笔图标；玩法门牌使用数字/字母 | 共享 Atlas 压低 Draw Calls；UI/对白另走多语言文本表 |
| 道路、区域间连接路、远景、布局 | Three.js 程序化生成 + 按材质合批 | 代码在 `src/morning/`，参数集中可调 |
| 重点门面道具、角色、车辆、地标 | Blender 5.2 LTS Python 脚本生成 GLB | 必须可无头命令行复现 |
| 通用贴图与印花 | 程序化绘制脚本（Pillow / SVG）或精简贴图 | 优先顶点色 + 有限贴图；单张贴图遵循 2 的幂次尺寸，无必要不上 2K/4K |
| 店铺与住宅室内 | 复用小房间基础模板 + 特色柜台/道具区分 | 不追求室内外物理 1:1 对应 |

**Blender 模块硬规则：**
- 所有硬边加倒角（Bevel），这是统一「厚实圆润」手感的关键；程序化方块也应改用圆角几何。
- 明暗与层次优先用顶点色（底部偏暗、角落 AO、轻度色彩过渡）与极轻手绘颗粒，**不做写实脏污/生锈贴图**，共用小贴图图集。
- 窗户、招牌、灯箱等**必须预先标记自发光区域**（独立材质或顶点色通道），供夜晚时段使用。
- **3D 样角先行**：制作新区域前，跳过 2D 风格重绘（paintover），直接用 Blender 制作约 **10m × 10m 的 3D 样角切片**放进实机验证材质、比例、Draw Calls 与骑行手感，确认后再批量扩展。

## 5. 性能与渲染硬预算

基线环境：Mac M2 / 中端笔记本 Chrome Metal，`1280×800`，`DPR 1`，目标稳定 **60 FPS**（数据来源：[`FIRST-ROAD.md`](FIRST-ROAD.md)）。

| 指标 | 预算 / 约束 | 核验方式 |
|---|---|---|
| 全帧 Draw Calls（含阴影） | 新增路段与城区目标 **≤ 250 calls**（老街历史追车位 310 calls 为已知超标项，新改动不得继续抬高） | Debug 面板 `#scene-perf` / `capture-scenes.mjs` |
| 全帧三角形数 | 目标 **≤ 100 万** | 性能核验与 Blender 导出面数控制 |
| 合批与实例化 | 同区块静态楼体/路面按材质合批；树木、路灯、电杆、稻穗、护柱等重复物**必须 `InstancedMesh`** | 代码审查 |
| 渲染防坑 | 禁止共面贴片导致 Z-fighting（如背板/招牌/标线需留明确法向偏移或单面剔除）；动态对象按需 `dispose` | 代码审查 + 多角度近景截图 |

## 6. UI / HUD 视觉约束

- 对白框、卡片与标签沿用 [`animal-island-ui`](../package.json) 体系与 `Noto Sans SC` 字体，圆润温暖、底部居中不遮主角。
- 所有新增或修改的 HUD / 手机 / 地图 / 对白界面，必须同时在 **PC 桌面（`1280×800`）** 和 **移动横屏（`844×390`）** 两个视口下截屏验证，确保无文字截断、按钮重叠、出屏或遮挡核心操作区。
- Debug 控件仅在开发模式、GitHub Pages 预览（`VITE_SCENE_DEBUG=1`）或 `?debug=1` 下可见；普通构建默认隐藏。
