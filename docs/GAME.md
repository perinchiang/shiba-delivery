# 阿柴快送｜当前有效游戏设计

> 本文是**唯一现行产品方向**，随明确决策原位更新；Git 保存历史，不新增 `GAME-v1.1` 之类并行规格。标记了「待验证」的内容不是已经批准实施的需求。

## 1. 产品定位【已确定】

**《阿柴快送 / Shiba Delivery》**：一款以**自由骑行、动物小镇与环境探索**为核心，以外卖配送为主要活动，以**轻度生活经济压力**提供长期动力的第三人称 3D 独立游戏。

主角是柴犬骑手阿柴。玩家在小镇、村庄与乡间道路间接单、取货、送达、返程，认识当地动物居民，体验忙碌生活中短暂的自由。游戏以温暖、可爱、有风景与音乐的氛围为主；挣钱与债务可以带来取舍，但不是惩罚性生存模拟的唯一目的。

优先级：
1. **骑行本身值得玩**：驾驶手感、道路节奏、风景转换、稻田和环境音乐。
2. **小镇有生命力**：有辨识度的店铺、动物居民和少量有意义的室内交互。
3. **经济压力有意义**：金钱、时间、电量与房租促成订单选择和故事，而不只是刷数值。

设计取舍：新增功能若不能改善上述任一支柱，默认暂缓。

## 2. 发行与开发方式【已确定】

- **正式发行优先 PC / Steam**；其他平台暂不承诺。这里指上市顺序，**不是**要求仅用 PC 原生程序开发。
- **开发期始终需要可使用的网页版本和清楚的交互 UI**，用于快速试玩、调整、美术审查和功能验证。现有 Three.js / Vite 原型可以继续发展，**最终发行打包技术尚未锁定**。
- 开发期必须有**可见且可点击的 Debug 面板/按钮**，尤其是将阿柴**瞬移至已实现的场景或测试地点**（如街道、店铺、小区或乡间路段——仅在这些场景实现后才出现）。跳转应同步处理角色/车辆位置、摄像机、碰撞、任务与交互状态，不能依赖手动修改控制台变量。其他适用的开发操作可按实际测试需要增加。
- Debug UI 属于开发工具；正式玩家 UI 不默认显示。
- 骑手手机在骑行和步行时露出可辨认的机身上沿，常显时间和当前订单目标，展开查看订单、切单和接单。地图独立打开，显示当前位置、取送点与路线。骑行中需要改变方向或靠边时显示短提示；步行时靠店招和现场动作键找到入口。

## 3. 世界与建筑【已确定的方向】

- 长期目标是**连贯、可骑行的动物小镇与村镇道路网络**，包含从密集街道驶向开阔稻田、河岸、村庄或住宅区的环境变化。希望未来容纳**五六公里左右的远单**，但当前不锁定地图尺寸、现实比例或必须耗时。
- 世界应当**视觉上完整、制作上有选择**：大量建筑只需要可信外立面；少量有订单、故事或功能价值的地点允许进入。玩家接单后必须能识别正确入口，不能靠猜哪些店可以进。
- 室外优先**程序化楼体、模块化立面与统一材料**。精修包子铺/药店门面、道具、招牌等可用 Blender 资产嵌入统一街道；不把每栋楼整栋独立建模当成默认方案。
- 店铺室内使用**独立、可复用的小房间模板**（柜台、店员、少量道具、特色细节）；不要求建筑内部物理上与完整外立面一一对应。
- 小区可用复用的大堂、电梯、楼层走廊与门牌；室外侧重门岗、道路、必要园林和建筑轮廓。电梯不必物理模拟整栋楼的逐层空间。
- 柴犬与摩托车现有卡通造型和比例为美术基线；动作采用可信接触关系与适度夸张，不为拟人化动作随意拉长腿或缩小车。

**村道画风试样：** 以立体造型、有限色板和清晨侧光衔接老街与乡道。镇口先入开阔青黄水田，弯前由齐阿柴头盔高的金黄熟稻收拢视野，近处稻穗随车速摆动，驶出稻浪后看见石牛、石桥和河面。稻丛和路边道具使用 Blender 模块，道路、水体和布局继续程序化生成。是否沿用到其他路段，待样段试骑后决定。

**树木造型：** 老街、村口和桥头使用同一套 Blender 阔叶树。树干短胖，蜜棕色的干身略鼓，圆根贴地，木结用淡色块表现。一条低枝斜向街边伸出，对侧的枝肩较高，偏心的顶冠与两侧叶团之间留着高低错落的轮廓。叶面以青绿、灰绿和嫩黄绿画出成对的宽叶，外缘用少量有厚度的叶尖投下阴影。店前树冠收紧，桥头树冠横向舒展。老街店前的人行道宽约 4.7 米，树池排在临车道一侧，用一圈凸起的陶砖围住泥土，店门一侧留出连续的步行空间。

**待验证：** 第一间特色商铺采用「程序化楼体 + Blender 门面道具」与「完整 Blender 外立面」的实际观感及维护成本；动物 NPC 的骨架与动画可复用程度；长路段性能、植被与风景生产管线。

## 4. 骑行手感【方向已确定，参数待验证】

- 老街两张配送单目前保留约 20 km/h 的手感供对照。自由骑行的默认最高速度已定为 50 km/h，覆盖城市十字路口和村道。调试时仍可切换 32.4、25 或 35 km/h 做对照。
- 后轮在加速时轻轻扬尘，明显制动或压弯时短暂留下胎印，力度随实际动作变化。自由骑行采用低速强起步、车速上升后推力减弱的电机曲线；高速打方向更缓，松手较快回正。下拉摇杆或按 S 先刹停，停稳后继续按住 0.35 秒才开始倒车。
- 目标是**起步轻快、开阔路段可提速、弯前有时间收油**：清楚的加速曲线、过弯倾斜、随速度变化的镜头与风声、胎噪，让开阔路段有「风吹过来」的感觉。
- 车速、游戏内时间流速与地图尺度三者的换算关系，在第一条长路段验证时确定，并写回本节。在此之前不锁定远单的骑行耗时。

## 5. 玩法与经济【方向已确定，数值待验证】

基础循环：**接单/选单 → 骑到商铺 → 取货 → 骑行配送 → 送达/交互 → 返程或继续接单 → 生活结算**。

- 近单与远单的收益、时间、电量、返程空跑等带来策略取舍，同时保留让玩家愿意绕路看风景的空间。
- **房租必须参与长期经济循环**。当现金不足时，允许通过欠租、宽限、债务与居民事件延续故事；**不默认因为某一天没赚够钱就立即 Game Over**。
- **贷款/借款与偿还是希望探索的玩法**，让经济困境产生荒诞而有意义的选择；是否开放、利息/处罚与结局规则待原型验证，不预设无限复利惩罚。
- 初期核心决策资源优先考虑**金钱、时间、电量**；不默认叠加饥饿、疲劳、健康、心情等复杂数值系统。疲惫可以先用角色动画和演出体现。

**已同意的方向（具体形式待验证，排期见 [ROADMAP](ROADMAP.md)）：**

- **骑行电台**：在手机或车上收听本地电台，DJ 串场播报小镇新闻与居民八卦，同时承担骑行音乐。
- **风景拍照收集**：沿途有值得停下的风景点，用骑手手机拍下收入相册，给「绕路看风景」一个正当理由，与赶时间形成拉扯。
- **天气与时段**：雨天、黄昏等让同一条路多次骑行产生变化；雨天可提高报酬但增加骑行难度。
- **居民好评取代平台星级**：居民记住阿柴、给予回应，而不是冷冰冰的评分，以温和的方式调侃外卖平台评分制度。
- **车辆小升级**：电池、保温箱、车筐挂件、贴纸等，给赚钱一个房租之外的正向出口；外观类优先于性能类。

**待验证：** 房租结算周期、订单报酬、充电成本、债务上限与缓解途径、叙事节奏、长期成长机制。

## 6. 当前原型【状态，不是最终规模】

**当前原型：** 榕湾老街有药店单与包子早餐单，覆盖接单、骑行、步行进店、取货、装箱与签收。自由骑行入口位于待接单的骑手手机内，从老街往东经过榕湾中路十字路口、镇口、稻田和河桥，抵达村口。十字路口可转进两侧各约 50 m 的横街。首条村道中心线约 1.25 km，可双向通行和中途下车。手机展示实测里程，地图显示当前位置和沿路地标，调试面板能跳到沿线地标、稻田样段和田埂近景。

**榕记包子铺：** 门面样板已通过美术验收，楼体沿用程序化模块，临街档口使用 Blender 蒸笼与包子。早餐单在门头右侧进店，与师傅交谈后从内堂柜台提走餐袋。内堂与药店共用小房间的地面、墙体和出入口布局，以蒸台、揉面案板和取餐柜台区分店铺。柜台交餐对白使用 [Animal Island UI](https://github.com/guokaigdg/animal-island-ui/tree/v4.0.0) 的 Card、Tag 和 Noto Sans SC 中文字体。对白框底部居中，四角使用不对称圆弧，圆角矩形名字牌左上叠放并露出半截。点击对白框、名字牌或按 E 接过包子。

后续阶段顺序与过关标准见 [ROADMAP](ROADMAP.md)；首个长路段**不要求**完成完整五六公里世界。

## 7. 待决产品问题

以下问题尚无决定，不得由开发者自行假设；最迟在 ROADMAP M2 结束前确定：

1. **语气比例**：治愈为主带少许讽刺，还是更直面外卖骑手的现实辛苦？
2. **游戏结构**：是否有主线与结局（如还清某笔债），还是开放式生活模拟？
3. **目标时长**：一部可玩完的作品（如 4–8 小时），还是可长期游玩？
4. **骑行取向**：偏街机（轻松好操作）还是偏拟真（惯性、刹车距离）？路上是否有车流和红绿灯？

## 8. 当前明确不做 / 不自动扩张

- 不把整个世界制作成「所有店铺可进入、所有房间真实存在」的重型开放世界。
- 不为了上下车动画更像真人而重做阿柴、摩托车比例。
- 不在第一阶段同时实现复杂饥饿/疲劳/健康与完整贷款经济模型。
- 不把 PC 发行目标误解成删除浏览器试玩、触屏入口和开发调试工具。
- 不因为脑暴、历史 Commit 或旧文档提过某项功能，就自动恢复或启动开发。

任何明确决定变更，都应在同一任务中原位更新本文；实现状态应以实际代码和测试为准。
